1. Why Hybrid Signatures Beat Single-Primitive Designs

Migrating directly from classical elliptic curves to lattice-based post-quantum schemes introduces a subtle engineering trade-off: lattice cryptography (Module-LWE / Module-SIS) resists Shor’s algorithm, whereas Ed25519 has twenty years of battle-tested classical cryptanalysis and tiny 64-byte signatures.

AuraChain Quantum implements a strictly conjunctive Hybrid Signature Suite across both the Rust validator node (fips204 + ed25519-dalek) and the browser wallet (@noble/post-quantum + @noble/curves):

  • Deterministic Dual Key Derivation: From a single 32-byte master entropy seed, domain-separated NIST FIPS 202 SHA3-256 KDF branches derive both an Ed25519 keypair and a deterministic NIST FIPS 204 ML-DSA-44 keypair (`1,312`-byte public key, `2,420`-byte signature).
  • Quantum-Shielded Address Commitment (aura1q…): Account addresses are aura1q || hex(SHA3-256("AURA-QUANTUM-ADDR-v1" || ed25519_pk || mldsa44_pk))[0..40]. Until an account signs its first outgoing transaction, neither public key is revealed on-chain—adding SHA3-256 preimage shielding on top of lattice hardness.
  • Dual Verification Rule: Consensus rejects any transaction unless both the Ed25519 signature and the NIST FIPS 204 ML-DSA-44 signature verify against the exact canonical signing preimage and match the sender's aura1q… commitment. Forging a transaction requires breaking Curve25519 and Module-LWE simultaneously.

3. Atomic Git-Tree CAS: A Publicly Verifiable Zero-Cost Cloud Ledger

Traditional cloud blockchains hide state inside proprietary SQL or NoSQL databases where operators can silently rewrite rows. AuraChain Quantum’s cloud validator uses Atomic Git-Tree Compare-And-Swap (CAS) backed by github.com/sanzaya-p/aurachain-ledger:

  1. Every newly produced block is written as an immutable JSON blob under blocks/<height>.json alongside updated head.json inside a new Git tree pointing to the exact parent commit SHA.
  2. The validator updates refs/heads/main with force: false. Git’s fast-forward invariant guarantees strict optimistic concurrency: if a concurrent instance raced ahead, GitHub rejects the ref update and the node cleanly reloads and retries.
  3. Every block in history has an immutable Git commit timestamp and SHA—publicly auditable by anyone with git clone at $0.00 infrastructure cost.
